**Shipped:**
- `src/walle/envelope.py` (new). The untrusted envelope (D55).
  - `wrap(text)` defaces the text, then puts it between `<<<untrusted:ID>>>` and
    `<<</untrusted:ID>>>`. `ID` is 16 hex digits from `secrets` and is new for every result.
  - `deface(text)` follows two rules. First, two or more opening angle brackets, then an
    optional `/`, then `untrusted` in any case, up to the closing brackets: the whole span
    becomes `[forged marker removed]`. Second, any other run of three or more angle brackets
    becomes guillemets, so `<<<` and `>>>` never appear in a body. Fullwidth, small-form and
    CJK brackets count, and invisible format characters between them are skipped.
  - `unwrap(block)` is strict. It accepts exactly one envelope with matching ids and nothing
    around it, or raises `ValueError`. Tests and host-side readers use it; the server doesn't.
- `src/walle/labels.py` (new). The `_meta.ifc` labels (D84), computed as D97 says.
  - `closure(events, ref)` is the ref and everything its `caused_by` reaches. A cycle still
    ends.
  - `integrity` is `untrusted` if any event in the closure has an actor other than `user` or
    the principal's own name. A ref missing from the map fails closed.
  - `confidentiality` takes the most restrictive label over the closure. Today that is always
    `private`, because every event lives in one principal's folder (D32).
  - `ifc` returns both in FIDES's shape. It is a pure function, with no IO and no model.
- `src/walle/mcp_server.py` (new). The FastMCP server and the `walle-mcp` command.
  - `recall(query)`: current beliefs only. A ref fetches that one belief (D81's index mode).
    Otherwise words are matched as prefixes, ranked by match count and then newest first, up
    to `RECALL_LIMIT` = 5.
  - `remember(text, summary)`: calls `staging.remember` with `actor="mcp"`. It writes one
    proposal and never an assertion.
  - `why(ref)`: the `caused_by` chain with each step's status.
  - Every piece of log text is a separate content block, with a fresh envelope and its own
    `_meta.ifc`.
  - Annotations follow D84: `recall` and `why` are `readOnlyHint: true, openWorldHint: false`;
    `remember` is `destructiveHint: false`.
  - `schema_cost` measures the `tools/list` answer a client receives. `walle-mcp --measure`
    prints it.

**Why:**
- **D48.** The first thing that ships is an MCP server plus a CLI. This is the MCP half, with
  three tools.
- **D55.** Recalled memory is an injection vector into the host. Every result is wrapped,
  and the id changes per result, so one leaked id unlocks nothing later. Anything shaped like
  a marker is defaced first, so the only markers in a result are the envelope's own two. The
  repo is public, so a fixed marker would be a password printed in the source.
- **D84.** Hosts that read labels get `_meta.ifc`. Hosts that don't still get the envelope.
  It is one claim in two forms.
- **D97.** Integrity is computed from the provenance closure, never assigned. No event has a
  label field, and the label is recomputed on every call and stored nowhere.
- **D48 and D86.** `remember` only stages. Nothing durable is written ahead of a person's yes,
  and the result tells the model so.
- **D102.** The schema cost is measured on what a client actually receives, and the 400-token
  cap is a test.

**Two-runner walkthrough:** the server writes only through `staging.remember` and reads only
through `index.update`, `index.load_records` and `index.ancestors`. It adds no lock of its own.
Each tool call runs in a worker thread, and every lock is an `flock` on a fresh `open`, so two
calls in one process lock against each other the same way two processes do.
- Writer A is the MCP server's `remember` on `d-mbp`. Reviewer B runs `walle review` on the
  same principal.
  1. A appends its proposal under the `d-mbp` stream lock, `fsync`s it and releases the lock.
     It never takes `staging.lock`, because a new proposal changes nothing B is deciding. This
     is the same as W in `staging.py`'s walkthrough.
  2. B, holding `staging.lock`, runs `index.update`. That takes `index.lock` and then every
     stream shared. B either sees A's proposal, or A's append is blocked until B drops the
     stream locks. Both are fine: the proposal is staged either way, and the next review shows
     it.
- Reader R is `recall` while writer W appends an assertion.
  1. R's `index.update` takes one cut under shared stream locks. W's append is either in the
     cut or waits for it.
  2. R folds, labels and wraps only the records that cut committed (`report.records`), so
     every label's closure is complete.
- Reader R is `why` while W appends.
  1. R takes `update`, then `ancestors`, each under its own lock, so W can land between them.
  2. If the ref asked about is W's new event, `ancestors` has it and `records` doesn't. The
     labeller then saw an unknown ref. The stranger pass caught this (below), and the fix merges
     the chain's own events into the map. That is enough because the index refuses a dangling
     ref (D111), so every ancestor of an indexed ref is indexed too.

**Review:** `agent-review` failed on `079c9a3` (1 high, 1 medium, 2 low, 1 nit). Fixed on the
same branch:

- **High, quadratic `_FORGED_RE`.** Rule 1 is now `envelope._forged_spans`: find each
  `untrusted`, look backwards for the bracket run, scan forwards to the closing brackets or the
  end of the line. Each character is visited a bounded number of times. `deface` on 32,000
  brackets, with or without zero-width characters, now takes milliseconds (it took 38 s and
  87 s). `tests/test_envelope.py` has hostile-input timing tests (limit 1 s), and an oracle test
  that runs the old regex against the new scanner on 4,000 random small strings built from
  brackets, gap characters, `untrusted` and newlines; they agree on all of them.
- **Medium, unbounded `recall`.** Each body is cut to `RECALL_TEXT_LIMIT` (2,000 characters,
  ending in an ellipsis), the same way `why` cuts to `WHY_TEXT_LIMIT`. The cut happens before
  `deface`, so it is also a second bound on the work done.
- **Low, a principal named `mcp`.** `build_server` refuses a principal named after any
  non-person actor (`mcp`, `user`, `observer`, `proposer`, `curator`, `kernel`).
- **Low, paths in `OSError` text.** `_describe` gives an `OSError` only its `strerror` (or "no
  log for this principal"), never the file name.
- **Low, stale check output.** Re-stated below.
- **Nit.** The `recall` description is passed to `@server.tool(description=...)`; the `noqa` is

**Choices made inside the task:**
- **`remember` writes as `mcp`, not `user`.** The text is the host model's words. Under D97,
  anything kept from it stays `untrusted` even after a human keep or edit, because the
  proposal stays in the closure. That is strict, and D97 says exactly that. A reviewer who
  wants a person's edit to count as their own words is proposing a new decision.
- **Trusted actors are `user` and the principal's own name. Everything else is untrusted**,
  including an actor this build has never heard of. The rule fails closed.
- **The integrity label comes from a Python walk over the records, not
  `index.ancestors`.** The records are already loaded for the fold, and a pure function over
  events is the form D97 describes.
- **Recall is prefix word matching, not FTS5 or embeddings.** It is deterministic and cheap.
  D34's retrieval is a later task. The index's `events_fts` table is unused here; using it
  would mean adding a query to `index.py`, a shared file, so I kept to new files.
- **`why` repeats `why.explain` without its `index.update`.** That lets a read-only profile
  get an answer from the index as last built. Changing `explain`'s signature would have
  touched `why.py`.
- **Token estimate: 3 characters per token, not the hook's 4.** Schema JSON tokenizes denser
  than prose. At 4 the same listing is about 276 tokens. I chose the number that makes the cap
  harder to pass.
- **`summary` defaults to `""`, not `None`.** A string default costs fewer schema tokens than
  `anyOf [string, null]`. An empty value means "derive it from the text", the CLI's rule.
- **The warning that enveloped text is data appears once per answer**, in a plain first
  block, not inside every envelope. This is the short-envelope option from Session 8's notes,
  since `recall` may be called several times a turn. The `recall` description says it too.
- **Module name `mcp_server.py`, not `mcp.py`.** `walle.mcp` and the `mcp` SDK would share a
  name in every file that imports both.
